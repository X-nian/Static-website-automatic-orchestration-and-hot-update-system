# 有证据的风格学习与历史总结

学习前读取档案当前规则、相关历史修订和采集完整度；不将整个历史库反复塞进每次生成上下文。

## 规则的作用范围

规则至少记录：`rule_id`、明确描述、`scope`、`status`、`origin`、证据ID与修订、独立创作数、反例、置信度及理由、创建/最后确认时间、被替代规则和变更原因。

`scope` 分为创作者/品牌、账号、平台、栏目/内容类型、本次创作。`status` 使用 `explicit/stable/candidate/disputed/retired`，`origin` 使用用户明确偏好、本人历史、最终稿差异或参考账号。独立的参考账号规则不能自动变成本人习惯。

适用冲突按以下顺序处理：本次明确要求 → 同范围用户明确偏好 → 更具体范围内已确认规则 → 已有稳定通用风格 → 候选观察。两个同范围明确要求互相矛盾时，以用户清晰的最新修正为准；含义仍不明确才问一个具体问题。

例如“这次结尾不要推广”只作用于本次；“以后都别用夸张承诺”是长期规则。不得把每个局部改稿意见自动提升为全账号规则。

## 样本计数与过拟合

同一素材的跨平台改写、同一创作多稿、同一帖重抓或修改均只算一个独立创作。合作推广、节日活动或单一栏目可单独聚类，不代表账号日常风格。

明确偏好按其作用范围立即生效。推测模式在至少3个独立且已批准/本人发布的创作中成立，且不存在未解释的强反例时，才可升级stable。只有同一专题样本时仅对该专题有效。独立性未知时使用保守计数并保持candidate，不靠猜测凑足3次。

候选规则可以作为可解释的参考，不能覆盖已确认偏好或在报告中称为确定习惯。反例出现后先判断栏目、平台或活动差异；无法解释则标disputed。以证据数量、独立性、时效、完整度与反例说明置信度，不输出假装统计校准的精确概率。

公开发布说明内容曾被采用，不证明每个措辞都是稳定偏好。未经用户确认的AI草稿不能成为本人风格样本；外部合作、代写或引用片段不能默认当作本人习惯。本人批准AI草稿可作采用证据，但不要把同源模板衍生稿重复计数。

## 历史分析产物

`history-summary.md` 应包含：实际时间/数量覆盖、常见主题和栏目、各平台内容形态、最近与早期的变化、重复表达/选题，以及无法分析的缺口。对新主题建议标明是建议，不伪装为历史事实。

`style-profile.md` 汇总声音和措辞、开头/结构/结尾、标题、视觉习惯、平台差异和明确禁用表达。每条重要结论给代表证据和适用范围；无画面或字幕时留空对应结论，不从文字推断。

互动表现仅在同平台、相近发布时间和内容类型内辅助比较。记录曝光等分母是否可得、指标观测时间、合作推广影响和样本限制。缺少分母不能计算互动率；不能把高播放直接归因于文风。

## 生成时如何使用历史

按目标账号和平台先过滤，再按内容类型、栏目、主题、最近已确认程度选择通常3—5篇完整度足够的范例。优先代表日常风格及用户满意的内容，不只选最火的帖子。样本不足时使用实际数量并说明。

每条范例只提取相关片段或结构要点，保留原文定位。一般风格规则可跨平台复用，具体格式必须区分；不搬运无关历史事实、旧价格、效果或第一人称经历到新素材。案例原话只在用户意图允许且确有需要时引用。

生成清单记录实际应用的规则ID、范例ID和修订ID。没有适合某平台的历史时用该平台的临时写作默认，并标明尚未学到该平台本人风格。

## 从最终稿学习

确认创作与版本关系后，比较被使用的草稿与最终稿，将变化分为事实纠正、风格调整、平台格式、活动要求和其他。事实错误要修正来源与校验流程，不能学习成文风；活动限定调整只写入活动范围。

未知是否采用的标题候选不记为用户拒绝。保存每条反馈的前后片段、修改类别、适用范围、证据和推断依据，再据独立性更新规则。相同前后版本和同一字段的反馈去重。

每次风格变更保存新版本和差异摘要，标出规则新增、缩小范围、争议或退役。用户要求撤销某个推断时回退该规则或指定版本，不抹掉过去发布和反馈记录。
