# 采集、风格与草稿验证

根据实际发生的工作记录验证，不把“文档描述了该流程”写成测试通过。各平台验证独立，必须附账号范围、时间、执行方式和观察证据。

## 验证状态

- `not_run`：没有执行；注明缺账号入口、登录、数据或工具。
- `passed`：预先约定的检查有证据满足，注明覆盖范围。
- `partial`：部分检查完成，列明已测与未测。
- `failed`：实际执行不满足，保存原因和复现位置。

结构校验、合成数据演练、真实账号采集和用户风格确认是四类不同结果。任一类别通过都不能替代其他类别。

## 首次真实账号最小验证

1. 确认账号身份和授权范围，记录入口及可用的获取方式。
2. 默认每平台检查3条已知内容，尽量含一条多媒体内容；不足3条按实际数量报告。
3. 对照详情页面核对标题、正文起止、作者、时间；视频核对字幕覆盖，图文核对实际获取的图片和图中文字。逐字段标完整度。
4. 再获取同一条确认去重；如有已知修订则验证变更可识别，没有真实修改样本就标该项未测。
5. 中断/重试恢复使用独立合成数据测试，不通过故意修改账号内容来制造失败或旧文编辑。

至少一条完整内容可证明“该账号这一内容类型可读取”，不能证明全部历史可枚举。未跑真实平台时报告not_run。

## 本地行为演练

在隔离目录使用明确标注synthetic的内容，不能写入真实风格库。验证以下场景和结果：

| 输入条件 | 应有结果 |
|---|---|
| 一篇帖子重复出现或重抓 | 一条逻辑帖子，不增加独立样本数 |
| 旧帖正文变化但发布时间没变 | 新修订，旧修订保留 |
| 只有浏览量改变 | 新指标观察，不增加正文修订或样本 |
| 保存帖子前中断 | 不能推进到丢失该帖的游标；可恢复待办 |
| 一条详情失败、其他成功 | 已成功内容保留，失败有可恢复队列及缺口 |
| 档案新鲜但有到期重试 | 执行到期重试；不因24小时缓存跳过 |
| 三个平台版本属于同一次创作 | 通用规则只计一次独立证据 |
| 只有标题、简介，无视频字幕 | 不声称学会口播风格或完整结构 |
| 用户说“这次不要推广” | 只影响本次，不改长期偏好 |
| 同标题有两次创作 | 最终稿保持待关联，不自动匹配 |

只检查指令包含上述文字不是行为验证；需要实际运行操作或独立执行案例并检查保存结果。可用工具不支持某步骤时如实记录未测。

## 风格验证

有足够历史时按独立创作划分训练样本与留出样本，例如至少10个独立创作时留出约20%、最少2个。先锁定留出ID，同创作的跨平台版本放在同一组；学习规则和选择范例均不得读取留出内容。既有风格档案已接触过某内容时不能再把它称为未见过的留出样本。

从训练样本建立测试档案，再比较留出内容体现的实际风格与测试档案的预测，报告符合、冲突、无法判断和证据。样本不足就做小样本定性检查，不能虚构准确率。真实最终裁判是用户是否认可；模型自评明确标为自评。

## 每次交付前检查

- 各平台核心事实、数字、时间和承诺与新素材一致；没有杜撰经历、效果或来源。
- 使用的规则有正确范围、版本及证据；缺少某平台/媒介证据时有说明。
- 各平台采用不同表达方式、结构和行动引导，不能只有标题不同。
- 篇幅与信息量匹配；没有叙述目的的事实重复应删减，不能靠反复换句话说制造长文。
- 依据可取得的当前平台限制检查长度、字段、标签和媒体；无法验证的限制标为未核实。固定格式样式不能覆盖用户本次需求。
- 草稿清单中的文件实际存在，版本与内容对应，选题/来源/风格记录可追溯；复制区内不夹带分析或待核对说明。
- 必须补充的事实单独列出；不要将含有未解决关键占位的稿件称为可直接发布。

发现可自行修正的问题先修正；缺业务事实则明确列出，不靠推测填充。

## 发布后效果

在用户提供批准/最终发布版本时记录返工轮数、主要修改类别和最终采用情况。编辑量应给出明确口径，例如同一规范化文本的字符级差异，且不能作为风格好坏的唯一指标。需要耗时数据时记录用户实际反馈或可观测时间，不从对话间隔推测工作耗时。

关注：事实纠错是否减少、同类风格修改是否反复、跨平台适配是否被保留。没有真实反馈时这些指标填未知；播放量或点赞只能辅助观察，不能证明风格学习成功。
