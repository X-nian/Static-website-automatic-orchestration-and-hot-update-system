# AIGC 镜头工坊

将「复杂镜头拆解」与「素材按用途验收」结合。默认使用中文，先给可操作结果，术语随用随解释。不要混入生成方案排名、金额或成本分析。

修改现有项目或继续上次工作时，先读取该项目已有的交付记录、素材档案和未完成项。项目记录放在项目交付目录中，不写回本技能目录；不要把一个项目的角色、配色或素材沿用到另一个项目。

## 路由与范围

- 用户给剧情、动作或镜头需求：拆镜头 → 提示词 → 示意图 → 检查。
- 用户给现有提示词并要求优化：保留核心意图，修改冲突描述；新定稿提示词对应新示意图。
- 用户仅要求检查已有素材：检查实际图片或视频并输出问题；不自动生成图片，不擅自修图。用户要求写修正版提示词时，再进入提示词与示意图流程。
- 仅讨论 skill、提供文章大纲或举例讲解提示词，不触发图片生成。用户明确说只要文字、不要出图时，以该要求为准。
- 只处理本次请求的镜头范围。长剧本按用户指定段落执行；范围不清且会导致大量生成时，先问要处理哪一段，同时可整理现有剧情，不把整部剧本默认为生成任务。
- 不修改网站、自动发布或制作最终视频。交付提示词和图片不意味着其他应用已经执行生成。

## 1. 明确用途和必须保留的条件

从现有消息与素材提取：剧情目的、人物身份与服装、道具、场景、画幅、目标风格、镜头前后状态及目标工具（如已指定）。不要反复询问已知信息。

只对会改变剧情或身份等关键缺失提问；普通构图选择可作明确标注的建议。没有指定工具时，用通用自然语言，不编造专有参数或模型时长上限。

将参考图标明用途：人物身份、场景空间、风格、道具，或实际编辑目标。先查看本地图片再作判断或引用。缺少必要参考时，不宣称已保持角色一致；若仅允许概念设计，标明示意人物。

首次使用一组素材时，按 [素材与连续性记录](references/continuity.md) 建立简洁档案：角色 C01、场景 L01、道具 P01，记录真实文件路径、参考用途、不可改项与用户确认状态。只登记本任务实际使用的素材。复用既有编号；用户改设定时新增版本并标明受影响镜头，不覆盖旧记录。

先确定少量可观察的硬条件，再谈好看与否。不同用途的检查依据见 [验收参考](references/review.md)。

## 2. 拆解镜头，同时维护连续性

一个镜头围绕一个主要叙事目标，可以包含自然连贯的多个动作，不按动词机械拆分。

优先检查：动作是否互相抢占展示时间；机位是否与画面范围矛盾；关键道具是否可见；起始姿态是否支持动作；转场是否丢失观众需要的信息。

需要拆分时，逐镜给出稳定编号 S01、S02 等、叙事作用、景别与机位、主要动作、起始状态和结束状态。只在有帮助时给建议时长，并说明是剪辑建议而非工具保证。

连续镜头固定人物外观、服装、道具持握侧、进出方向、相对站位与主要光源。允许剧情需要的变化，但说明变化在哪一镜发生。不能通过拆分暗中删掉关键动作或改变结局。

逐镜记录规划的起始/结束状态，并与前后镜头核对；把生成结果中实际可见的状态另行记录，不以规划代替观察。明确「人物自身左右」与「画面左右」，机位变化导致屏幕方向变化时，不机械判为错误。切换场景、时间跳跃或有意跳切时标注理由。具体字段见连续性参考。

没有真实失败视频时，把判断标为「设计风险」，不写成「已发现模型故障」。

## 3. 分开写静态关键帧与动态提示词

每镜只保留必要信息：人物/主体、场景、构图、动作、光线和必须保持的条件。用具体描述替代堆叠修饰词；不强制所有镜头采用同一模板长度。

- **视频提示词**：描述起始状态、动作顺序、镜头运动与结束状态。
- **示意图提示词**：从该镜头中选一个明确时刻，描述这一帧可见的内容。用于理解提示词时，默认选最能说明内容的关键帧；用户需要图生视频输入时，优先选能启动动作的起始帧。两种用途不兼容时说明取舍，不把动作完成帧误交为起始帧。
- 只有一个画面不能表达必要变化，且用户要求覆盖变化过程或需要首尾帧时，才补结束帧；否则默认每镜一图。需要增加的帧必须标明时刻与用途，不能用一张图同时表现两个时刻。
- 不让单张静态图同时完成互斥的起止姿态，也不把静态示意图称作完整动作预览。
- 如果本次只做静态素材，只写图片提示词，不加无关的视频指令。

使用 [交付记录](references/delivery.md) 将镜头、提示词版本、图片和检查结论对应起来。初稿使用 v1，修订时增版本，不覆盖原图。

## 4. 自动生成对应示意图

当交付新的、供实际使用的镜头或图片提示词时，默认自动调用内置图像生成工具，逐镜生成一张对应示意图，不再询问是否需要配图。一个镜头若同时包含视频提示词和关键帧提示词，不因此重复生成；仅按前述明确的首尾帧需求增加图片。

调用前读取当前可用的 `imagegen` 技能，遵循其工具与保存规则。默认使用内置 `image_gen`，不是自行写 API 脚本。若内置工具不可用或失败，保留已经完成的提示词，明确标记该图「未生成」，不以搜索图、空框或旧图冒充，不擅自切换付费 API 路径。

每个独立镜头用独立生成调用，不用一张拼图代替用户应得到的各镜头图片。用户只要概览时才采用联系表或故事板排版。

调用时传入该版本的示意图提示词及实际需要的参考图，具体参数遵循当前 `imagegen` 技能和工具接口，不依赖本文件中的固定参数名。区分参考图与编辑目标，不附无关历史图片。无法包括必要参考图时，要求重新提供，不猜图像内容。

若为视频提示词制作配图，在结果旁说明「此图展示该镜头的起始帧/指定关键帧，未验证动作效果」。其他工具生成的实际结果可能不同。

这属于用户请求执行期间的自动配图流程，不是后台监听服务，也不创建定时任务。

每次调用前在交付记录写下镜头号、提示词版本、帧用途与「待生成」；调用返回后立即保存真实结果路径并标为「已生成、待检查」，检查后再更新结论。分阶段保存，不等所有镜头结束。

续接时按记录核实图片是否存在、是否对应当前提示词与素材版本，只处理缺失、失败或已过期的项目。已完成且仍匹配的图直接复用。若上次调用结果不明，先检查已有工具结果与文件；无法确认则标「结果未知」，不直接重复调用。单镜失败时继续完成不依赖它的工作；依赖其状态的后续镜头标明阻塞原因，不能伪称连续性通过。

## 5. 检查实际输出，有限修正

查看生成结果或用户提供的素材，按硬条件和用途验收。分别记录「画面检查」「跨镜一致性」「动态验证」；每项注明已检查／待验证／不适用及覆盖范围。已检查的部分再给以下结论之一：

- 可用：当前已检查范围内符合用途。
- 需修改：具体局部问题，给出位置、影响和修改建议。
- 需重做：核心构图、身份或动作条件不符合用途；说明重做原因。

无法查看、信息不足或不能从静态图判断时，标为「待验证」，不得强行判可用。每项结论区分实际观察与推测风险。技术尺寸等要求必要时读文件属性；不要仅凭画面猜测。

例如可以交付「画面检查：已检查，可用；跨镜一致性：待验证，缺少上一镜；动态验证：待验证，目前仅有关键帧」。抽帧检查应写出检查的时点，不等同看过完整视频。不要以一个笼统的「可用」覆盖未完成的验证。

发现问题先定位层级，再决定改什么：

- **画面执行问题**：提示词清楚，但输出未遵守；优先修图或重新生成，保持正确提示词的核心要求。
- **提示词问题**：描述冲突、遗漏或指代不明；先修词，再为新版本生成图。
- **镜头设计问题**：动作展示、机位或叙事目标难以同时成立；先改分镜，保留剧情信息，必要时提出拆分方案。

多个原因都可能存在时写成待验证假设，不断言模型故障。不要靠堆叠提示词修补结构性分镜问题，也不要为了迁就错误生成结果而改写用户要求。

对本次自动生成的示意图，发现明显违反核心条件时，可自动做一次有针对性的修正并复查。若仍不满足，保留版本并说明原因，停止自动重试。仅审查用户现有素材时，不自动编辑。后续用户继续要求修改，则按新请求处理。

修改某镜头时复核相邻镜头的相关状态，并查找引用被修改素材的其他镜头。只把相关记录标为待复核，不重新生成无关镜头。若新的定稿提示词改变画面内容，原示意图标为旧版本，生成新图对应；仅标点或排版变化不重复出图。自动修正的一次上限按本镜头本轮任务累计，不因换问题层级或版本编号而重置。

## 6. 交付

先展示图片与对应镜头提示词，再给简短结论和必要的修改建议。多个镜头可用简洁表格总览，详细提示词分镜呈现。

将用户要复用的文本、图片和记录保存到当前任务允许的交付目录（本环境使用 `outputs/`）；不要让项目依赖只停留在临时目录。图注注明镜头号、版本和示意时刻，状态表明确已生成、已检查或待验证。最终只声称实际完成的检查。

用户没有提供素材时，不要求测试数据；可做明确标注的概念示意，但不编造实测表现或通过率。
